# micro:bit プログラミング教材としての評価・レビュー

このプロジェクト（`study-microbit-with-test`）は、**micro:bit 用の方位磁石（コンパス）アプリケーション**を題材に、3つの異なる言語・実行環境（Python, TypeScript, MakeCode/PXT）での実装と、それぞれの環境に応じたテスト手法（TDD、ユニットテスト、シミュレータテスト、CI/CD）を統合的に学習できる非常に優れた教材です。

本ドキュメントでは、本プロジェクトを「プログラミング教材」という観点から多角的にレビューし、そのメリットや特徴、さらに教材としての価値を高めるための改善提案をまとめます。

---

## 1. 教材としての構成とアプローチの評価

一般的な micro:bit の学習は「MakeCode でブロックを組み立てて動かす」という初級レベルで終わりがちですが、本教材は**「組み込み開発における品質保証とソフトウェアエンジニアリング（テストと設計）」**に焦点を当てており、中上級者向けとして極めてユニークかつ価値の高いアプローチを採っています。

### 🌟 主なメリットと特徴
1. **多角的な言語アプローチ（Python / TypeScript / MakeCode）**:
   同じ「方位判定ロジック」を3種類の言語/環境で実装することで、それぞれの言語仕様の違いやプラットフォームの特性（MicroPython vs. MakeCode API）を比較学習できます。
2. **テストファースト（TDD）の体験**:
   各プロジェクトでテストがファーストクラスとして扱われており、コードを書く前に仕様をテストコードとして表現する習慣（TDDワークフロー）を身につけることができます。
3. **ハードウェア依存の分離とモックの学習**:
   「センサーから値を取得する（ハードウェア依存）」と「方位角から方角文字列を計算する（ロジック）」を分離する設計を学べます。また、テスト時にハードウェア API をどうモック（擬似化）するかという、組み込み開発で最も重要なスキルを習得できます。
4. **自動化と CI/CD の統合**:
   Git commit/push 時の Husky によるフック、GitHub Actions による自動 CI、カバレッジ測定など、現代のプロフェッショナルなソフトウェア開発パイプラインを micro:bit 開発を通じて実践できます。

## 2. プロジェクト別・教材としての詳細評価

### 📁 `sample-compass` (Python 実装)
- **言語・環境**: MicroPython (micro:bit 標準のファームウェア環境)
- **テスト**: `pytest` + `unittest.mock`
- **教材としての評価**:
  - `from microbit import compass, display, button_a, Image` といった標準的な MicroPython API を使用しており、実機での直接動作に適しています。
  - テストコード（`test_compass.py`, `test_compass_integration.py`）では、`unittest.mock` を使って micro:bit のセンサーやディスプレイオブジェクトをモック化しています。これにより、**「実機がない環境でもロジックのテストを実行する方法」**を非常にクリアに学ぶことができます。

### 📁 `sample-compass-ts` (TypeScript 実装)
- **言語・環境**: TypeScript + Node.js
- **テスト**: `Jest`
- **教材としての評価**:
  - micro:bit のデバイスライブラリに一切依存しない、純粋な TypeScript ロジックとして実装されています。
  - **「関心の分離（Separation of Concerns）」**の好例です。デバイス特有の処理を排除してピュアなロジックにすることで、テスト実行速度が圧倒的に速くなり、テストカバレッジ 100% の維持が容易であることを体験できます。
  - 型定義（`Direction` など）を適切に活用した、堅牢なプログラミング手法の学習に適しています。

### 📁 `sample-compass-makecode` (MakeCode 実装)
- **言語・環境**: TypeScript (MakeCode/PXT 互換)
- **テスト**: `pxt run` + カスタムテストランナー (`simulator-test-runner.cjs`)
- **教材としての評価**:
  - 最も実用的な micro:bit 開発環境である MakeCode での動作を保証するためのプロジェクトです。
  - 特筆すべきは、PXT CLI のシミュレータ機能 (`pxt run`) を Node.js 側から制御し、シミュレータ上でアサーションログをパースして成否判定する仕組みです。**「ブラウザやシミュレータ環境におけるテスト自動化」**という、実務的で高度な技術を学べる点に大きな教育的価値があります。
  - `namespace Compass` と `%block` アノテーションによるカスタムブロック定義が含まれており、MakeCode 独自拡張（Extension）の開発手法も学べます。

## 3. 教材としてのさらなる改善提案

本教材をさらに教育効果の高いものにするための提案です。

### 💡 改善提案 1：Python 環境の解説と MakeCode Python（Static Python）への言及（※対応済み）
* **現状**: `sample-compass` は MicroPython を前提としており、`import microbit` を行います。
* **対応**: 
  - `sample-compass/README.md` に標準 MicroPython と MakeCode Python の違いを詳しく説明する対比表を追記しました。
  - MakeCode の Python モードと完全な相互変換ができる Static Python 実装である [`compass_makecode.py`](file:///Users/katoy/github/study-microbit-with-test/sample-compass/compass_makecode.py) を新規追加しました。

### 💡 改善提案 2：MakeCode カスタムブロックの視覚的ドキュメント化
* **現状**: `compass.ts` には `%block` などの MakeCode 独自アノテーションが記述されていますが、これがどのようにブロックとしてレンダリングされるかの説明が少ないです。
* **提案**:
  - `sample-compass-makecode` の README に、このアノテーションによって生成されるブロックのスクリーンショット、または「MakeCode エディタにインポートした際にどのように拡張ブロックとして表示されるか」の手順を加える。

### 💡 改善提案 3：エッジケースのハンドリングと学習者への課題（エクササイズ化）（※対応済み）
* **現状**: キャリブレーションがされていない状態で方位を測定しようとした場合のエッジケース対応が不足していました。
* **対応**:
  - **Python版**: 未校正時は `"CAL"` と警告表示を流し、センサーから `-1`（エラー値）を検知すると未校正状態に戻る処理を実装。
  - **TypeScript版**: 未校正時は `Error` をスローする例外エラーハンドリングを適用。
  - **MakeCode版**: 未校正なら `"CAL"`、エラーなら `"ERR"` を表示。また、テスト時にハードウェア制御を安全にスキップする `skipHardware` フラグとテストモードを導入しました。
