# 動画チュートリアル台本: micro:bit方位磁石をテストする

**対象**: プログラミング経験がある小学4年生以上  
想定尺は約18分です。画面には大きめのターミナル文字と字幕を表示し、テスト件数は台本へ固定せず、収録時の実行結果をそのまま見せます。

**事前準備**: 動画を見る前に [README.md](../../README.md) の「方位磁石とは何か」を読むことを推奨。

## 0:00〜1:00 オープニング

画面: micro:bit、MakeCodeブロック、Pythonテスト、TypeScriptテストを4分割表示。

ナレーション:

> 方位磁石は北がどこにあるかを教えてくれます。0度から359度の角度で返ってきます。
> この教材では、その角度を **8つの方位**（北、北東、東...）に変える方法を、ブロック、Python、JavaScriptの3つの言語で一緒に学びます。
> 完成コードを見るだけでなく、**自動テスト** で間違いがないか確かめる方法も学べます。

字幕: 「3つの言語で同じ問題を解く」

## 1:00〜3:00 全体構成

画面: ルートREADMEの「3つの実装」。

ナレーション:

> **MakeCode版**はブロック言語です。見た目で分かりやすく、実際のmicro:bitに書き込めます。
> **Python版**はテキスト言語です。ブロックより詳しく書けます。
> **JavaScript版**はコンピューターの上で動きます。実際のmicro:bitには直接書き込みませんが、論理を詳しくテストできます。

字幕（同時に画面に表示）:
- MakeCode = ブロック（実機対応）
- Python = テキスト（実機対応）  
- JavaScript = 論理検証（PCで動作）

ナレーション:

> 3つの違いはありますが、**やることは同じ**です。方位角という数字を、8方位という答えに変える。この同じ問題を、3つの方法で解くことで、プログラミングの本質が見えてきます。

## 3:00〜6:00 MakeCode

画面: `sample-compass-makecode/src/compass.ts`。

```typescript
_heading = input.compassHeading();
```

ナレーション:

> `input.compassHeading()` は「方位角はいくつか」と聞く命令です。返ってくるのは0から359の数字です。
> **注意**：`input.acceleration` は「傾き」を返すので、方位磁石の代わりにはなりません。

字幕: 「compassHeading（方位磁石）と acceleration（傾き）は別物」

画面: `main.ts` のボタンAと `basic.forever`。

ナレーション:

> Aボタンを押すと校正（セッティング）できます。foreverは「ずっと繰り返す」という意味です。
> テストの時は、シミュレーターに「今の方位角は何度」と決めておくコマンド（`setHeadingForTest`）を使います。

コマンド実行:

```bash
npm --prefix sample-compass-makecode test
```

末尾の成功メッセージを画面いっぱいに拡大表示。

ナレーション:

> テストが全部通った（✅）ということは、ブロックが正しく方位を判定できたということです。

## 6:00〜10:00 MakeCode Pythonと境界値

画面: `sample-compass/src/compass_makecode.py` の方位判定。

```python
if heading < 22.5 or heading >= 337.5:
    return "N"
```

ナレーション:

> ここが難しいところです。北（N）だけは 0 度を中心に左右に広がっています。
> 359度も北だし、1度も北です。この「360度をまたぐ」という部分が、プログラムが間違いやすい場所です。
> だから境界値テスト（ちょうど境目の数字でテストする）が大事なんです。

字幕: 「北（N）だけが 360度をまたぐ → ここがバグしやすい」

画面: `sample-compass/test/test_simulator.py`。

ナレーション:

> このテストは、micro:bitの実物とは違い、**ブラウザ上のシミュレーター**を使っています。
> PCには磁気センサーがないため、テストプログラムが「今度は45度」「今度は90度」と命令します。
> LED表示は確認できますが、実物のセンサーの精度や、実機特有の問題（配線ミスなど）は保証できません。

```bash
npm run test:python
```

字幕: 「シミュレーター = 実物を完全に再現できない」

## 10:00〜13:00 TypeScript（JavaScript）

画面: `sample-compass-ts/src/compass.ts`。

```typescript
export type Direction = 'N' | 'NE' | 'E' | 'SE' | 'S' | 'SW' | 'W' | 'NW';
```

ナレーション:

> JavaScriptでは、戻り値に**どんな値が返ってくるか**を事前に決めておくことができます。これを「型（かた）」と呼びます。
> 北、北東、東...西北の8つだけが返ってくる、ということを宣言しています。

画面: `sample-compass-ts/test/compass.test.ts`。

```typescript
expect(Compass.headingToDirection(337.4)).toBe('NW');
expect(Compass.headingToDirection(337.5)).toBe('N');
```

ナレーション:

> 337.4度は「北西（NW）」、337.5度は「北（N）」という期待値をテストに書きました。
> 期待値の通りなら✅、異なるなら❌が返ってきます。

コマンド実行:

```bash
npm --prefix sample-compass-ts test
```

字幕: 「型システムが「あり得ない値」を防ぐ」

## 13:00〜16:00 品質チェック（すべてが正しいか確認する）

画面: ルートターミナル。

ナレーション:

> ここからが大事です。3つの言語のテストを全部実行して、**どれか1つでも間違っていないか** 確認します。

```bash
npm run test:all
```

ナレーション:

> `test:all` はいくつかのチェックをまとめて実行しています：
> 1. Pythonの構文が正しいか
> 2. JavaScriptが正しくビルドできるか
> 3. テストが全部通るか
> 4. コードの何%がテストされているか（カバレッジ）

字幕: 「test:all = 複数の安全チェックをまとめて実行」

ナレーション:

> もし1つでも失敗したら、❌と表示されて、プログラマーはそこを修正します。すべて成功すると ✅ が出ます。
> 実機用ファイル（HEX）のビルドは、MakeCode版だけに対応しています。

成功時の出力を画面いっぱいに拡大表示。

## 16:00〜17:30 実機またはシミュレーターで動かす

ナレーション:

> テストがすべて成功したので、いよいよ実際に動かします。

### 実機がある場合

ナレーション:

> MakeCode HEXファイルを micro:bit へ書き込みます。Aボタンで校正（北の方向にそろえる）して、Bボタンで方位を表示します。

実演画面: micro:bitを回転させると、LEDが方位を指さす様子を見せます。

### 実機がない場合

ナレーション:

> ブラウザのシミュレーターでも大丈夫。命令に従って Aボタンで校正し、Bボタンで画面に方位が表示されることを確認します。

ブラウザ画面を見せます。

字幕: 「テスト = 数字で確認、実機 = 目で確認」

## 17:30〜18:00 まとめ

ナレーション:

> プログラミングの流れをまとめます：
> 1. **目で確認** → 実際に動かして、どう動くか見る
> 2. **テストで確認** → 数字で、間違っていないか詳しく調べる
> 3. **実機で確認** → 本物の micro:bit で最後に確認する
>
> この順番なら、micro:bit を持ってなくても、ブラウザだけでも学習を進められます。
